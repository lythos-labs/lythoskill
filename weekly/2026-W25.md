## Project Lesson Candidates

1. **ZK Review 的三层验证**：文档可读性（Level 1）→ 执行可验证性（Level 2）→ 跨模型一致性（Level 3）。本周验证了 Level 2 的必要性：阅读 9/10 的 agent 执行时降到 5/10，因为输出层 UX 问题对文档审查不可见。

2. **Agent 自主性培养**："Don't auto-fix drift without understanding why" + "Use git log to see what changed" 比直接给修复命令更能建立 agent 的探索能力。本周 ZK 执行测试中，agent 主动用 `git log` 调查 epic drift 原因，而不是等待指令。

3. **Onboarding 摩擦的系统性解决**：一个 agent 的困惑（"skill-deck.lock 要不要 commit?"）暴露了一个架构设计缺陷（lockfile 混用声明式和运行时）。解决它（ADR-20260616000939948）不仅消除了当前摩擦，还建立了"相对路径在 lock、绝对路径在 state"的跨机器一致性原则。

4. **Prompt 设计即接口设计**："Read and explain" 和 "Execute and report" 是两种完全不同的测试模式。前者测文档，后者测 agent 行为。AGENTS.md 的内容再好，如果 agent 的 prompt 不告诉它"执行"，它就不会执行。
