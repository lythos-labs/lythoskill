## TL;DR

lythoskill was created in a 48-hour bootstrap sprint (April 23-24) with no prior project state. The first commit at 12:45 on April 23 bundled the entire thin-skill monorepo scaffold: project-cortex GTD governance (ADR/Epic/Task/Wiki probes), skill creator, and the foundational thin-skill pattern ADR. Within 30 minutes, deck governance was ported from skill-manager and accepted as a core component. By end of day 2, 14 ADRs had crystallized the architecture, curator@0.2.0 was published, and lythoskill had dogfooded its own deck link to clean the user's personal `~/.claude/skills/` from 8 skills to 2. **The single most important decision**: the thin-skill pattern itself — heavy logic lives in npm packages, the skill layer is a thin router. Every subsequent component (deck, curator, arena, scribe) inherits this layering.

## Project Lesson Candidates

- **文件探索只能恢复约70%的上下文** — handoff 必须 dump 探索无法恢复的 30%：踩过的坑、真实 working tree 状态、具体的下一步。这个教训直接塑造了 project-scribe 的职责边界。
- **Handoff 价值 = 任务结构复杂度 x 接力需求** — 简单恢复平局 (7/10)，复杂接力完胜 (10/0)。Control agent 陷入 194 次调用零产出的无限探索陷阱，因为没有 inherited frame。
- **版本号是承诺不是装饰** — curator 本地 0.4.0 vs npm 0.1.0，开发时随手写版本号是坑。Publish 前必须检查 npm 现状。
- **"满意" (emotional) ≠ "LGTM" (operational)** — 29 个文件跨 session 遗留的根因是情感确认和操作确认是两个不同的信号。
- **Cold pool + deck link 到项目级别是最稳定的治理架构** — 全局扫描应覆盖冷池 + 活跃池 + 项目本地 skills。
