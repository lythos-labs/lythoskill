# Glossary — Project Jargon Baseline

> The vocabulary table for tribal knowledge (黑话). Sessions compress
> information density, so handoffs drift into jargon with no provenance —
> a zero-context reader's only recourse is git log/blame archaeology. This
> file is the fix: the ZK reviewer's baseline, and the deposition target for
> recurring terms.

## Deposition rules

- **Recurring jargon** (used in ≥2 handoffs, or user-coined shorthand a
  zero-context reader cannot resolve from AGENTS.md alone) → add a row here,
  with a source-of-truth pointer. **No source, no entry.**
- **One-off jargon** → do not deposit; gloss it in place (one sentence) in
  the handoff that uses it.
- Definitions must be self-contained — a reader holding only AGENTS.md +
  this file must resolve the term without opening the source, or the
  source pointer is doing the definition's job.

## Terms

| Term | Definition (self-contained) | Source of truth |
|------|----------------------------|-----------------|
| **ZK Review / ZK agent** | A zero-context reviewer agent (no project knowledge, no session memory) reads an artifact and reports what it cannot understand or execute. ZK agents are sensors, not bosses — their findings are signal for the author's judgment, not commands. | `packages/lythoskill-project-cortex/skill/references/zk-review.md`; AGENTS.md § ZK Review Gate |
| **Pass-by-reference** | When spawning a reviewer/subagent, pass file PATHS (the artifact + AGENTS.md), never pasted content — the file stays the single source the reviewer reads at its own path. | AGENTS.md § ZK Review Gate |
| **SSOT** | Single-source-of-truth doc — the one canonical file for a topic; other docs link to it instead of restating. Git + filesystem remain the territory; SSOT docs are the compass layer on top. | AGENTS.md ("SSOT is a compass, not a database"); `cortex/wiki/04-ssot/` |
| **Trailer dispatch** | Commit-message trailers (`Closes: TASK-xxx`, `Task: TASK-xxx review`, `ADR: ADR-xxx accept`) parsed by the `.husky/post-commit` hook, which auto-creates one follow-up commit per trailer line. | AGENTS.md § Commit Trailers; `.husky/post-commit` |
| **Lock-step versioning** | Every npm package + the root share exactly one version; a bump is monorepo-wide via `bunx @lythos/skill-creator bump` — never hand-edited (no jq/python). | `cortex/adr/02-accepted/ADR-20260502233119561-bump-command-and-lockstep-versioning-policy.md` |
| **skill-deck.lock** | Machine-generated snapshot of the deck's resolved state (resolved paths, content hashes). Derived state, regenerated by `deck link`/`deck refresh`; git-tracked, goes dirty by design when linked skill content changes. | `packages/lythoskill-deck/skill/SKILL.md` § Key Concepts; `references/architecture.md` |
| **Cold pool / working set** | Cold pool = local store of all downloaded skills; the agent never scans it. Working set = symlink-only directory the agent actually scans (default `.claude/skills/`). | `packages/lythoskill-deck/skill/references/glossary.md` |
| **Player** | A CLI agent runtime that arena can drive (claude, codex, deepseek-harness/dsh, …). Decks are the tested side; players are the driving side. | `cortex/wiki/01-patterns/2026-05-02-player-deck-separation-and-tcg-player-analogy.md` |
| **Probe** | A preflight check CLI. Two senses: `cortex probe` (repo governance health — stale tasks, epic drift, empty shells) and player/adapter probe (version-range check; fail-closed = refuse to run when out of range). | AGENTS.md; `packages/lythoskill-agent-adapter` (probe contract — fail-closed version range) |
