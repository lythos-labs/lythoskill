# ADR-20261023182817984: Dynamic views are queries, generated indexes are projections

## Background

"Latest daily file" has been expressed as filename ordering:

```bash
ls daily/*.md | sort | tail -1
```

That encodes a semantic query ("latest by date") into an implementation detail
(lexicographic position), and it has failed twice:

- **2026-04-23 → 2026-05-05:** `daily/README.md` sorted after every `2026-*.md`
  under *both* en_US.UTF-8 and POSIX collation, so `tail -1` returned the README.
  On 2026-05-05, `cf74e930` added `daily/_README.md` and `87dd6017` deleted the
  old `README.md` (two commits, neither titled as the rename; daily notes call
  it "sort fix").
- **2026-05-05 → now (latent):** the rename only works under en_US collation.
  Under `LC_ALL=C` / `env -i`, `_` (0x5F) sorts *after* digits (0x32), so
  `tail -1` selects `_README.md` again. Reproduced 2026-10-23:
  `env -i sh -c 'ls daily/*.md | sort | tail -1'` → `daily/_README.md`.

An external review of the same defect argued the opposite repair: turn every
dynamic view into a command (`daily latest --json`), with `INDEX.md` demoted to
a query cache. That framing matches what `cortex` already does — `cortex index`
generates `cortex/INDEX.md` — but its "must be a command" step was asserted
without accounting for where the command would run.

## Decision Drivers

- Correctness must not depend on collation or on the absence of non-date files.
- The affected skills ship to **adopter projects**; onboarding/scribe are
  skill-only packages (`packages/lythoskill-project-onboarding/` has no
  `package.json`, no bin). A command is unavailable exactly where the skill runs.
- `daily/*.md` has **no frontmatter `status:` field** (0 of 51 `.md` files at
  this commit; 50 dated + `_README.md`), so a
  `latest = date max + status valid` query has nothing to read without first
  migrating the write side (scribe).
- `cortex` already demonstrates the target shape: read models are generated
  (`generate-index.ts`), committed as cache, never hand-edited.
- One observed failure mode does not justify a new package boundary (AGENTS.md
  hard rule 10, "price the edge case first").

## Options

### Option A — Command-ize (`daily latest --json`)
**Pros**:
- Single semantic home; testable in code.
- Evolvable output (`{path, commit, next_commands}`) without changing callers.
- Consistent with `cortex list` / `probe` / `deck status`.

**Cons**:
- Adds an install/runtime prerequisite to a read path that today needs none;
  adopter projects with only the SKILL.md text get no query at all.
- Needs a host package. `cortex` is wrong (governance state, not session
  journal); a new package is new publish/release surface.
- The advertised semantics ("status valid + has handoff section") do not exist
  in the corpus; implementing them means a schema migration across 51 files and
  a change to scribe's write path, for one consumer.

### Option B — Date-filtered shell query (chosen)
```bash
ls daily/ 2>/dev/null | grep -E '^[0-9]{4}-[0-9]{2}-[0-9]{2}\.md$' | sort | tail -1
```
**Pros**:
- Zero dependency; runs in any project the skill is copied into.
- Collation-independent: after filtering, every sort key is ASCII digits and
  `-`, which order identically under en_US and POSIX.
- Non-date members (`README.md`, `_README.md`, notes) are structurally excluded
  rather than out-sorted.
- The write-once carrier already exists: the skill's `references/`.

**Cons**:
- The one-liner is duplicated across shipped surfaces (onboarding, scribe-weekly,
  AGENTS.md, SSOT wiki) because those packages install independently.
- No machine-readable output; freshness stays prose for the agent to judge.
- No automated test enforces it (see Impact → Negative).

### Option C — Hand-maintained `daily/INDEX.md`
**Pros**: one stable path.

**Cons**: stale by construction. This is the failure the project already rejects
for `cortex/INDEX.md` ("generated, not hand-edited"). A hand-written pointer is
a second write target for scribe and will drift within a week.

## Decision

**Choice**: Option B.

Dynamic views are queries; materialized indexes are permitted only as **output
of a query**, never as a second source of truth. Concretely:

1. "Latest daily" is a *predicate over dated filenames*, not a position in a
   sort. Shipped skills carry the date-filtered query above.
2. `cortex/INDEX.md` remains the model: generated by `cortex index`, committed
   as cache, never edited.
3. `daily latest` as a command is **deferred**, not rejected. The trigger for
   revisiting is a second consumer that needs the result as data (e.g. weekly
   emitting machine-readable cross-references) — at which point the natural host
   is the scribe package (CQRS is model separation, not deployment separation).
4. `daily/*.md` gains no `status:` frontmatter under this ADR.

**Rationale**: the defect was the query implementation, not the idea of a query.
Option B fixes the implementation at the layer where the skill actually runs;
Option A relocates the query to a layer the adopter may not have, and imports a
schema migration that today's corpus cannot pay for.

## Impact

- Positive: one deterministic rule for "latest", independent of locale and of
  directory contents; no new package, no schema change.
- Negative: the one-liner is repeated across independently installable surfaces;
  no automated guard, so the unfiltered form can be reintroduced by a future
  edit. Accepted because the surfaces are prose snippets and a grep-based guard
  would be learned around (same reasoning as probe-not-detecting-decisions).
- Follow-up:
  - [ ] Revisit command-ization when a second consumer needs `latest` as data
        (host: scribe package, not cortex).
  - [ ] If a `status:` field ever earns a user, migrate scribe's write side
        first; do not filter on a field the corpus does not have.
