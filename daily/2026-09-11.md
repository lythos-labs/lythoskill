### Pitfalls

- **变异钉跑了个假的** —— 执行者第一次用了个**没匹配上**的 python anchor,所以那一次"钉"跑的是**未变异**代码,却报成"通过"。
  - **Wrong approach**: 用字符串替换做变异,不校验替换是否发生。
  - **Symptom**: 无 —— 它**绿**。这正是最危险的形态。
  - **Fix**: 变异后**先确认变异生效**(或看红数),再采信结果。执行者自己抓到并重做。
  - **Root cause**: 变异测试的"通过"和"什么都没做"长得一模一样。
  - **Time wasted**: ~10 分钟(执行者自查)。

- **测试与实现同源(F2)** —— 为这张卡写的交叉校验 helper **从被测模块 import 了 `statusToken`**。
  - **Symptom**: 移除首词规则后 `read()` 会**静默丢掉一行**(`| backlog (revised) |` 不再被折叠),而**全套测试仍然全绿**。
  - **Fix**: helper 用自己的 `firstToken`,并补一条判别性测试(M-PIN)。
  - **Root cause**: 卡自己的 Technical Approach **写着**「本仓已经为『同一处理解的第二份抄写』付过代价(**测试与实现同源**)」—— 警告在卡上,违规在卡的测试里。

- **夹具退化让钉失去效力(F4)** —— 出厂夹具 ID `TASK-20260101120000000`:月 `01`、日 `01`、本地 12:00。
  - **Symptom**: **三个**变异(朴素切片 / 月日互换 / 本地格式化)**全部 46 pass / 0 fail** —— 而"朴素切片"正是删掉那个函数存在的全部意义。
  - **Fix**: 换成 `TASK-20260101003000000`(本地 `[00:00,08:00)` 窗口)与 `TASK-20260509120000000`(月≠日);并在进程内固定 `TZ=Asia/Shanghai` + **断言赋值生效**;四个敌对环境时区复跑一致。
  - **Root cause**: 夹具落在函数的**退化点**上 —— 退化输入让多个变异同解。

- **我把测试搞红了** —— 归档 3 张卡**之后**,AC5 的测试硬编码了它们的**目录**。
  - **Symptom**: cortex `187 pass / 3 fail`,`bun run test` **exit 1**。

- **我用一个错误解释覆盖了一个正确的观测,还让别人改了记录** —— 执行者报「`bun test` 里子进程的输出看不见」,我在 `/tmp` 做了三条复现、看到 stdout 正常,于是断定它那个机制说法是幻觉,并让它把记录改成「测试不得依赖宿主环境」。
