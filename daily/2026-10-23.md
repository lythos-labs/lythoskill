- **模板迁移只立 ADR 不改代码**：实际故障面 = 2 张 completed task 卡 + 1 张 archived epic 使用 asset-only 标题；按"先有用户再改结构"，迁移留 follow-up。Ref: ADR-20261023183001417 § Impact。
- **外部认知按"结构对、事实回仓核对"处理**：结构判断（view 应为 query）成立；"六个月"实际是 README 12 天（04-23→05-05）+ `_README.md` locale 潜伏 5.7 个月。

### Pitfalls

- **文件名排序不是日期排序**：`README.md` → `_README.md` 的"排序修复"只在 en_US 成立；`LC_ALL=C` / `env -i` 下 `_`(0x5F) 排在数字(0x32)之后，`tail -1` 又选中 README。
  - **Wrong approach**: 用前缀字符逃出排序（`_` 前缀）。
  - **Symptom**: 默认 locale 正确，无 LANG 的 shell（CI/Docker/非交互 sh）静默读错文件。
  - **Fix**: 排序前用日期正则过滤，排序键只剩 ASCII 数字与 `-`。
  - **Root cause**: 把语义查询编码进 collation 的偶然顺序。
  - **Time wasted**: ~20 分钟（含复现与历史考古）。

- **"已命名的 drift"不等于"已修复的 drift"**：2026-09-11 的 drift-classes 已把模板四载体命名为 Class 1 Carrier drift；六周后形状仍然不同，因为没有任何东西拥有第二载体。Ref: `cortex/wiki/01-patterns/2026-09-11-drift-classes-*`。

- **ZK 走查抓出刚接受 ADR 的 3 个 P1**：初稿把模板载体数写成 3（实际 4，漏了 agent 真正被指去读的 `skill/assets/`）；"0 张 task 卡用旧标题"实际是 2 张；计数 52/397 实际 51/398。全部已就地修正，并把 `skill/assets/` 的删除 + `SKILL.md:444` 更新补进 follow-up。
  - **Wrong approach**: 以 grep 得到的第一个集合作为"全部载体"，未交叉核对 SKILL.md 的读取指令。
  - **Symptom**: ADR 的 follow-up 照做后，agent-facing 载体仍然存在，"one carrier" 名义达成、实际未达成。
  - **Fix**: ZK reviewer 零上下文重读，逐条回仓验证；ADR 在 push 前就地修正并标注 amendment。
  - **Root cause**: 已接受的 ADR 被当成"事实已完成"，未在 push 前做对抗性核对。
  - **Time wasted**: ~15 分钟（ZK 跑 140s，修正 3 处 + follow-up）。

- **pre-commit 钩子会重建并自动 stage `skills/` 镜像，与你 stage 的内容无关**：想让"源码一个提交、文档另一个提交"，钩子在第一次提交里就把镜像的 doc 改动带进去了，源码那半还留在工作区 → 有一次提交里镜像比源码新。
  - **Wrong approach**: 用 `git reset` 把 skill 源文件从 staging 里摘出来，指望镜像跟着一起留下。
  - **Symptom**: 提交成功，但 `creator align` 在那一刻会报不一致；`git show --stat` 里镜像变了而源没变。
  - **Fix**: 要么一次提交把源+镜像+文档一起带上，要么把它当成两次提交时在第二个提交里补齐源码。
  - **Root cause**: 钩子按"编辑器改变了东西"重建并 `git add`，不读你的 staging 意图。

- **迁移本身又暴露一对 drift**：ADR 只点了三个模板载体，执行时才发现 `skill/HANDOFF-TEMPLATE.md` 与 `assets/HANDOFF-TEMPLATE.md` 内容不同，且 `session-handoff.md` 指向一个从来不存在的 `${CLAUDE_SKILL_DIR}/assets/` 路径。
  - **Wrong approach**: 按 ADR 里 grep 出来的那份清单逐条执行，清单外的同型文件默认"不存在"。
  - **Symptom**: "one carrier" 完成后，handoff 模板仍是两份、其中一个指针仍然是死链。
  - **Fix**: 以"目录里所有同型文件"为准扫一遍（`find -name '*TEMPLATE*'` + 全仓 grep 指针），而不是以记忆里那几条为准；扫出来的同类项当场收编。
  - **Root cause**: follow-up 清单是上一次 grep 的快照，不是不变量。
