### 7. CI 验证流程教训（新增）

**Pre-push 不验证 example decks 远程路径** — 设计如此，原因：
- 远程验证需要 GitHub API，有 rate limit 风险
- 28 个 deck 的远程检查耗时较长
- 外部 skill repo 的路径变化属于**外部依赖变更**，非代码问题

**正确做法**：
- Push 后**主动检查 CI 状态**，确认 `validate example decks` step 通过
- 如果失败，区分：
  - `phase='repo-existence'` → repo 被删除/改名，需要更新 deck 或寻找替代
  - `phase='path-existence'` → 子路径被删除，需要移除或更新 skill 引用
