### Pitfalls / Lessons

- **trailer.ts 初始设计缺陷**: `4c5d598` (Claude 4.6 co-authored) 引入 `Task:` 分支时无前缀检查，导致 `Task: EPIC-xxx resume` 被错误路由到 `moveTask`。防御性补丁 + 架构修复双重解决。
- **ZK Review 收敛**: 两轮 ZK Review 后 gaps 从 6 个收敛到 2 个（均为探索友好），说明 task card 的动词映射表和 `handleTaskTransition` 设计有效。
- **post-commit trailer 状态机**: `Review:` trailer 尝试 `task review` 时如果 task 在 backlog 会失败（正确行为：只能 `start` → `in-progress` → `review`）。
- **skills/ rebuild 边界**: AGENTS.md 不是 skill 源文件，不需要同步到 skills/。只有 `packages/*/skill/` 更改才触发 pre-commit rebuild。
- **版本对齐时间差**: npm publish 和 git push 之间有时间差。如果 push 先于 publish，deck link 拉新 skill 但 bunx 调旧 CLI → 版本不一致。正确顺序：test pass → bump → publish → push。
- **Deck refresh 明确化**: `.agents/skills/` 是运行时工作集（symlinks），刷新需要 `bun packages/lythoskill-deck/src/cli.ts link`（或 `deck link`）。不是 npm install，是 deck 的 reconcile 命令。如果 `.claude/skills/` 为空或 stale，运行 `deck link` 即可，不需要重新 npm install。
- **skills/ 不是给本地 agent 的**: `skills/` 是构建输出，供外部生态消费（Vercel、静态站点）。本地 agent 通过 `deck link` 从 github 拉取，不是从本地 `skills/` 读取。
- **cold pool 边界**: `deck link` 从 `~/.agents/skill-repos/`（cold pool）拉取，不是从本地 `skills/`。cold pool 是 git clone cache，需要 `deck refresh` 或 `deck add` 更新。本地源码改了 → build → skills/ → push → github → cold pool 更新 → deck link 刷新工作集。
- **Semver 规矩（0.x 阶段）**:
  - patch: bug fix，无 API 变化（0.16.0 → 0.16.1）
  - minor: 新功能，向后兼容（0.16.0 → 0.17.0）— 如 `task <verb>` 子命令
  - major: 破坏性变化（0.17.0 → 1.0.0）— 0.x 阶段不急着上 1.0，灵活处理
  - 本次教训：`task <verb>` 是新 API 表面，应该用 minor 不是 patch。已修正 0.16.1 → 0.17.0。
