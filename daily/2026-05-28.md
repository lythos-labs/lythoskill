### Key Decisions

- **统一风格 > 豁免复杂度**: 用户决策——"减少心智记忆的价值大于 60 行改动"
- **豁免的隐藏成本 = 每个 agent 每次读代码时的认知税**
- **ZK agent 审计的价值**: 不假设业务逻辑，从零读测试代码，发现"这个测试到底在测什么"的歧义
- **Fork challenge 的必要性**: 审计者自己无法发现评级不一致和误报，需要外部挑战

### Pitfalls

- **"Respect current code" bias**: Agent 假设现有代码符合文档规范 → retroactively 辩护 → 从不质疑代码本身
- **Mock 魔法掩盖缺陷**: `spyOn(console)` + `process.exit = ...` 让测试碰巧通过，但从不验证真实行为契约
- **参数顺序陷阱**: `argv.find(a => !a.startsWith('-'))` 的语义与测试期望可能矛盾
- **测试标题/断言漂移**: mirror.test.ts "SOCKS fallback succeeds" 实际断言 `toBeUndefined()`
