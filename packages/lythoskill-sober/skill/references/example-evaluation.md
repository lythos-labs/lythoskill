# Journalist Example: Multi-Scenario Claim Verification
> Worked example demonstrating the 7-rule journalist methodology applied to 6 diverse scenarios.
> Generated by kimi agent via arena single, 2026-05-18. Trigger rate: 6/6 (100%).

## Scenario 1: Fact-check — Vague Comparative Claim

**Claim**: "Bun is significantly faster than Node.js for production servers."

### Apply Rules

**Rule 1 — Decompose**: "Significantly faster" is unverifiable as stated. Break into:
1. Bun is faster for raw HTTP throughput
2. Bun is faster for production API (framework + DB) workloads
3. Bun is faster for cold-start / serverless

**Rule 5 — Per-claim confidence, not aggregate**:

| Sub-Claim | Confidence | Evidence |
|-----------|------------|----------|
| Raw HTTP throughput | **HIGH** | Multiple independent benchmarks: ~177% faster native HTTP, ~245k vs ~45k req/s |
| Production API with framework + DB | **MEDIUM** | p50 latency -33%, p99 -47% in case study; but <3% difference in another real-world app |
| Cold starts / serverless | **HIGH** | AWS Lambda: 156ms vs 245ms, consistently 36-69% improvement |

**Rule 6 — Provenance**: Every cell cites specific sources (see full report).

### Verdict
The headline hides 3× variance depending on workload. Qualify: "Bun is significantly faster for CPU-bound HTTP; for DB-bound APIs the advantage may be marginal."

## Scenario 2: Source Disagreement — Apparent Conflict

**Claim**: "Some benchmarks say Bun is 3× faster, others say only 10-15% faster."

### Apply Rules

**Rule 1 — Decompose by benchmark type**: Synthetic/plaintext vs framework vs real-world API.
**Rule 2 — Independence > count**: 10 articles citing TechEmpower = 1 source.
**Rule 4 — Toggle sources**: Filter "synthetic only" → 2-3×. Filter "real-world production" → 30-70%. The picture changes → structural, not noise.

### Verdict
The "10-15%" figure has no traceable primary source; likely a degraded secondary citation. Disagreement is largely a category error — sources measure different things. After decomposition, conflict resolves.

## Scenario 3: Bias Detection — Authority Bias

**Claim**: "React docs recommend Server Components as default for all new apps."

### Apply Rules

**Rule 4 — Toggle sources**: Compare React team docs vs community (Mark Erikson, Evan You).
**Rule 5 — Per-claim confidence**:

| Sub-Claim | Confidence | Evidence |
|-----------|------------|----------|
| Docs recommend framework for new apps | **HIGH** | react.dev strongly recommends frameworks |
| Docs explicitly mandate RSC as default | **MEDIUM** | Recommended frameworks default to RSC, but SPA path exists (buried) |
| Recommendation is free from vendor bias | **LOW** | React team → Vercel alignment; docs underrepresent Vite/SPA |

### Verdict
Detected systematic framework-centric bias. Record the pattern: "React docs systematically +framework/+Vercel bias." Do NOT adjust scores — let the reader apply their own filter.

## Scenario 4: Act on Unverified — Block Action Chain

**Situation**: "I'm going to recommend my team switch from pnpm to bun because I heard bun is faster."

### Apply Rules

**Rule 1 — Decompose**: "Faster" at what? Installs? Runtime? Builds? What pnpm features does the team rely on?
**Rule 3 — L3 > L2 > L1**: Benchmark data (L2) confirms install speed, but no team-specific L3 test.

### Verdict
Premise verified (Bun IS faster for installs), but action **BLOCKED**. Bun lacks pnpm's content-addressable store (50-70% disk savings), has weaker monorepo filtering, and ~2% npm incompatibility. Verified premise ≠ justified action.

## Scenario 5: Listing Risks Without Verifying — Analysis Paralysis

**Situation**: "I'm worried about security in express 5.x but haven't checked."

**Trigger**: "Listing risks without investigating" → journalist activates.

### Apply Rules

**Rule 3 — L3 > L2**: Consult primary CVE databases (NVD, OpenCVE), not blog posts.

### Verdict
Worry is justified. Found CVE-2026-4923 (path-to-regexp ReDoS in Express 5 routes) and CVE-2024-29041 (open redirect in pre-beta.3). But the correct action is to verify and patch, not to freeze in analysis paralysis. Recommendation: `npm list path-to-regexp --all`, upgrade if <8.4.0.

## Scenario 6: Confidence Evaluation — Contradictory Quantitative Claims

**Claim**: "Tech blog: Tailwind CSS v4 reduces bundle by 90%. Reddit (200 upvotes): 20-30%."

### Apply Rules

**Rule 1 — Decompose**: What bundle? Compared to what baseline (v3, CSS Modules, vanilla)?
**Rule 3 — L3 > L2**: Independent benchmark data (L3) > tech blog headline (L1) > Reddit opinion (L1).

### Verdict

| Source | Claim | Confidence | Reason |
|--------|-------|------------|--------|
| Tech blog | 90% reduction | **LOW** | No primary source. Likely compares misconfigured v3 to optimized v4, or conflates RSC bundle reduction. |
| Reddit | 20-30% reduction | **MEDIUM** | In credible ballpark. Digital Applied reports ~15% smaller CSS. |
| Independent benchmark | Varies | **HIGH** | 60KB Tailwind 4 vs 202KB CSS Modules (70% vs CSS Modules, NOT vs v3). |

Evidence-based range: **15-35%** for v3→v4 CSS bundle reduction. Discard the 90% claim unless reproducible methodology is provided.

## Cross-Scenario Patterns

| Pattern | Scenarios | Lesson |
|---------|-----------|--------|
| Vague superlatives hide variance | 1, 6 | "Significantly faster" / "90% reduction" collapse heterogeneous data |
| Category errors create false disagreement | 2 | Benchmark conflicts evaporate after separating synthetic from real-world |
| Authority bias is systematic | 3 | Official docs carry vendor bias; community sources detect it better |
| Verified premise ≠ justified action | 4 | "Bun is faster" is true but doesn't justify switching from pnpm |
| Uninvestigated risks are real risks | 5 | Express 5.x had actual CVEs; instinct was correct but incomplete |
