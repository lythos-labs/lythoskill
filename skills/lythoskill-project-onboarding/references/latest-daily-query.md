# Latest Daily Query

> "Latest daily" is a predicate over dated filenames, not a position in a sort.
> Canonical rule: this file. Decision record: `ADR-20261023182817984`.

## Canonical query

```bash
# latest
ls daily/ 2>/dev/null | grep -E '^[0-9]{4}-[0-9]{2}-[0-9]{2}\.md$' | sort | tail -1

# latest N (e.g. weekly prep)
ls daily/ 2>/dev/null | grep -E '^[0-9]{4}-[0-9]{2}-[0-9]{2}\.md$' | sort | tail -7
```

`daily/` is the contract: one dated file per session day, `YYYY-MM-DD.md`.

## Why not `ls daily/*.md | sort | tail -1`

That form asks lexicographic position to answer a date question, and it has
failed twice in this repo:

| Period | Effect |
|--------|--------|
| 2026-04-23 → 2026-05-05 | `daily/README.md` sorted after every dated file under both en_US and POSIX collation → `tail -1` returned the README |
| 2026-05-05 → 2026-10-23 (latent) | Rename to `_README.md` fixed only en_US. Under `LC_ALL=C` / `env -i`, `_` (0x5F) sorts *after* digits (0x32) → `tail -1` returned `_README.md` |

Reproduction of the second:

```bash
env -i sh -c 'ls daily/*.md | sort | tail -1'   # → daily/_README.md
```

The rename fixed a symptom in one locale. The filter removes the class: after
`grep`, every sort key is ASCII digits and `-`, which order identically under
every collation, and non-date members cannot participate at all.

## Do not

- Do not `ls daily/ | tail -1` (relies on filename position).
- Do not add a second header/README in `daily/` and rely on its name to sort
  away — sorting is not exclusion.
- Do not introduce a hand-maintained `daily/INDEX.md`. A materialized view is
  acceptable only as the **output** of a query (see `cortex/INDEX.md`, which is
  generated by `cortex index`), never as a second write target.

## When a command is warranted

If a consumer needs the result as data (machine-readable path + commit + next
steps), prefer a command — but check that it can ship where the skill runs. The
skills here are installed as text into adopter projects; a `bunx` package is not
guaranteed to exist there. That is why this rule stays a one-liner.
See ADR-20261023182817984 § Options A/B.
